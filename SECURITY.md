# Security policy

Report vulnerabilities privately. Use **Security → Report a vulnerability** when
private reporting is enabled on this repository. If that option is unavailable,
use a contact route published on the maintainer’s GitHub profile to arrange a
private channel before sharing reproduction details. Do not put exploit details,
credentials or personal records in a public issue.

Include the affected revision, impact and minimal reproduction using synthetic
data. Test only installations and accounts you control. Public issue reports are
appropriate for ordinary bugs that do not disclose a vulnerability or private data.

Keep credentials, signing material, local databases, backups and operational logs
outside Git. Before sharing diagnostics, remove account/session tokens, device
identifiers, personal records and deployment-specific addresses. This policy does
not promise an audit, support period or response deadline.
